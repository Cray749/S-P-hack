# Limitations, assumptions and negative findings

This page exists so that nothing below has to be discovered by a reviewer. Numbers referenced here are
produced by `python -m tremor.backtest` and `python -m tremor.evaluate` (results in `data/results/`).

## What did not work (and what we did about it)

| Finding | Evidence | Consequence |
|---|---|---|
| Conditioning analogue weights on text, class or severity does **not** beat the unconditional historical spread at n = 36 | Expanding-window backtest, pinball loss; class-only conditioning was worst | The text kernel is kept deliberately soft (temperature 0.5). We do not claim retrieval predicts magnitude. |
| Impact derived from analogue severity had no rank-correlation with realised severity | Spearman |ρ| < 0.25, not significant | Impact is defined from observable evidence instead (a transparent triage score). It is **not** a calibrated forecast. |
| Promoter-group contagion cannot be backtested | Only one such episode (Adani 2023) in the library | The GROUP role falls back to a pooled distribution and is flagged as a fallback; no accuracy claim is made. |

What the data **did** support: text predicts whether an event is systemic or idiosyncratic. Drawing the market-wide move
from the crisis library with probability P(systemic | class) and from ordinary weeks otherwise improved pinball loss
over the unconditional crisis library (the table is fixed before evaluation; see `config.SYSTEMIC_PRIOR`).

## Data limitations

* **News timestamps are day-resolution** (FNSPID). We assume mid-session (15:00 UTC) publication. The corpus therefore
  cannot support any statement about minute-level lead or lag between news and social posts, and we make none.
* **Social posts carry no author id.** Social volume is capped at 0.5 of corroboration and can never confirm an event alone.
* **Replay window is 2020-04-09 to 2020-07-16.** Live ingestion works (POST /api/ingest) but a live free news feed is not wired.
* **Delisted names** (Silicon Valley Bank, Credit Suisse, DHFL, old Hertz) have no price history, so those episodes contribute
  market, sector and peer evidence but no direct-hit evidence.
* **Credit spreads are ETF proxies** (HYG/LQD versus IEF over assumed spread durations) because long FRED spread history is no
  longer freely available. The equity-to-credit sensitivity (kappa) is calibrated on these proxies across the 36 episodes.

## Modelling assumptions (all in `src/tremor/config.py`)

* **Credit triangle**: spread ≈ PD × LGD, with LGD 45 % (35 % for secured loans), i.e. Basel foundation-IRB style supervisory values.
* **Equity → credit**: s₁ = s₀·exp(−κ·r) with κ calibrated on the library (R² reported in `data/market/calibration.json`).
* **Loans** are valued by the change in lifetime expected credit loss (Δspread × min(tenor, 5y)). Bonds use duration, convexity
  and spread duration. Swaps use DV01 and a CVA add-on. Everything is a first-order simplification, not an IFRS 9 or FRTB engine.
* **Systemic prior** (`SYSTEMIC_PRIOR`) is a design table fixed before evaluation.
* **Impact score** weights (0.40 / 0.30 / 0.20 / 0.10) and the confidence formula are design priors, not fitted values.
* **Windows**: all analogue moves are the peak excursion within five trading days, measured on a common day per episode.

## The book is synthetic

Company names are real public companies used as labels. Ratings, tenors, notionals and swap sides are generated by a seeded
random process (`src/tremor/book.py`). The book is **not** anyone's real exposure, and loss ranges are illustrative, not capital numbers.
No confidential or client data of any kind is used.

## Statistical caveats

* About 30 backtest episodes and 150 scored intervals, with overlapping, non-independent episodes. Coverage near nominal means
  "not obviously miscalibrated", not "calibrated".
* Leave-one-out uses future episodes and is reported only as a stability check.
* The event study is concurrent (same-day), not predictive, and social posts partly react to the move.

## Engineering caveats

* The Dockerfile was written for, but not built on, the author's Windows machine (no Docker installed there). See README for the
  verification status.
* In-process pub/sub stands in for Kafka / Redis Streams to keep a cold start dependable; the consumer interface is unchanged.
* Embeddings are cached per document, so replay hashes are exact inside one environment. Across machines, tiny floating-point
  differences in the neural embeddings could in principle flip a near-threshold clustering decision.
